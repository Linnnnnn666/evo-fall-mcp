## 一、重新定位：缺口比原记录更严重

原记录写的是"去重检查永远不会命中"。复查后发现受影响的是**两条**检查，因为二者同源：
`_tool_name_conflicts()`（工具名冲突）与轮询器里的防重复去重，**都**经
`_installed_plugin_tool_names()` → `_load_plugins()` 去读 `plugins.json`。该文件从未被写入，
于是两条检查的"已装插件"维度**同时恒为空集**。

| 检查 | 修复前 | 后果 |
|---|---|---|
| 工具名冲突（"内置 / 已装插件 / MCP"三表中的"已装插件"这张） | 内置表、MCP 表有效；**已装插件表恒空** | 与已装插件重名的需求不会被拦 |
| 防重复投递去重 | **恒空** | 同一能力被重复投递 → DSH-2 重复构建、profile patch 重复挂载 |

## 二、改动内容（两处，纯增量）

| # | 位置 | 内容 |
|---|---|---|
| 1 | `_save_plugins()` 之后 | 新增 `_register_installed_plugin(req, req_name)`：把 DSH-2 建成的插件写入 `plugins.json`，并记 `plugin_installed` 审计事件 |
| 2 | `_run_dsh2()` 读需求状态的 try 块 | 原 `except Exception: pass` 扩为 `elif req.status == "done"` → 调用上面的注册函数；异常改为打印而非静默吞掉 |

设计要点：

- **以"文件真实存在"为登记前提** —— 需求标了 `done` 但插件文件已不存在的不登记
  （正是那两条已清理的市场插件的情形），并记 `plugin_register_warn`。
  注册表反映**已装现实**，不是纸面声明。
- **以需求文件的 `done` 为准** —— 延续"进程返回码 ≠ 结果，以产物为准"的既有原则。
- **幂等** —— 同名插件内容未变则不重复写盘、不重复记事件；"文件缺失"告警每进程只记一次。
- **未新增任何模块级依赖** —— 该文件无全局 `import time`（各调用点均函数内导入），
  新函数按同一风格在函数内导入。

## 六、本次新发现（如实记录）

### 1. 危险模式扫描用裸子串匹配 → `exec(` 会误报

装后扫描对新插件报出 `plugin_scan_warn: 检测到危险模式 ['exec(']`。复查确认是**误报**：
命中点是插件里正则的 `RegExp.prototype.exec()` 调用（解析日志文本的常规写法），与命令执行无关。

- **根因**：`PLUGIN_DANGEROUS_PATTERNS` 里的 `"exec("` 走的是裸子串匹配（`if p in content`），
  因此会命中任何 `.exec(`。
- **影响**：任何用正则解析文本的插件都会被判"危险模式，请人工复核"——长期的代价是
  运维对该告警脱敏（狼来了）。
- **修法方向**：改为"前面不是点号的 `exec(`"，需把扫描从子串匹配改为正则匹配。
- **本次未改**：这是安全扫描器的灵敏度取舍。扫描器"宁可误报"本身是合理设计，
  且消息写的就是"请人工复核"，故仅记录、不擅自降低灵敏度。

### 2. 去重分支被冲突检查"遮蔽"

修复后两条检查同源（都读 `plugins.json`），而工具名冲突检查在轮询器里**先**执行。
因此"工具名与已装插件完全相同"的重复需求会被记为 `rejected（工具名冲突）`，
而**不是** `skipped（已有相同能力工具）`。

- 期望的结果（不重复构建）已达成，验证第 3 项即为实证。
- 代价：`plugin_req_skipped` 这条路径对"精确同名"场景更难触发。
- 若要恢复语义区分，需让去重改按**能力语义**（而非工具名）判断——那是流水线逻辑改动，
  超出"不改架构"的范围，故未做。

## 七、可复用的经验

1. **"同源"是排查盲区**：两条看似独立的检查读同一个从未生成的文件，
   所以修一处不够——定位缺口时要顺着数据依赖往上找，而不是只看报错点。
2. **注册表要以"现实"为准**：以"文件真实存在"为登记前提，让已删除的插件无法被登记为
   已装能力。这条约束顺手把一个历史叙事不一致问题自动收敛了。
3. **修完要造一条"能证伪"的测试**：投一条本应被拦下的重复需求，看它**是否真的被拦下**，
   并检查 patch 文件 mtime 确认没有发生多余动作——这比"检查函数返回值"强得多。
4. **安全扫描器的误报也要记录**：误报不会造成安全风险，但会造成"告警疲劳"，
   而告警疲劳才是真正的风险。所以它值得进文档。
5. **让新工具解决它自己带来的问题**：审计事件补齐后日志变厚，正好用第五次进化造一个
   日志摘要工具——工具的用处是自证的。
